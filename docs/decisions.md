# Decisions: Green CI, Stale Deploy

## ADR Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-07-22 | Initial scaffold as factory-output | A minimal, runnable repro of a real bug class: a size-only sync step lets a byte-length-identical content change ship as a silent stale deploy while every CI signal stays green. |
| 2026-07-22 | Built the repro per `agentic-tekton`'s existing spec (`docs/samples/green-ci-stale-deploy.md`): `render.sh` (template a build), `sync-size-only.sh` (the bug, mirrors `aws s3 sync --size-only`), `verify-deploy.sh` (the fix, content-hash comparison), `tests/test-repro.sh` (asserts both properties empirically), CI runs the same script on every push/PR | The core design choice: make the test itself the demonstration, asserting both "the bug reproduces" and "the fix catches it" in one script that exits 0 only if both hold - keeps CI green while still proving something real, rather than an intentionally-red job that would make the repo look broken. |
| 2026-07-22 | Doubt-driven-development pass (single-model, `Explore` agent) found and fixed 8 issues, most severe a trailing-slash path bug and an unsafe `sed` substitution | A trailing slash on `<src>`/`<build>` broke the `${f#"$src"/}` relative-path stripping in both `sync-size-only.sh` and `verify-deploy.sh`, nesting files under the entire absolute path instead of their real relative name - fixed by stripping trailing slashes on every directory argument. `render.sh`'s `sed` substitution crashed on a `/` in the date string and silently corrupted output on `&` (sed's replacement-side special characters) - replaced with a bash parameter-expansion substitution. Also fixed: `find` failures on a missing/typo'd source directory were silently swallowed by `set -e` inside process substitution (now an explicit upfront existence check); the README overclaimed `verify-deploy.sh` as a symmetric build-and-live check when it's actually build-to-live only (disclosed, matching `engine-gateway-lab`'s own real "artifact vs live" design's documented v1 scope); `scripts/lib.sh` missing from the README's file listing; an unanchored `build/` `.gitignore` pattern. |
| 2026-07-22 | Cross-model review (`codex exec --sandbox read-only`, gpt-5.5) found and fixed 4 more real issues, one revealing a bug in the single-model round's own fix | **The bash parameter-expansion fix from the prior round was itself incomplete**: verified directly against bash 5.3, `${var//pattern/replacement}` ALSO treats a literal `&` in the replacement as "the matched text," the exact sed-ism the switch to bash was supposed to avoid - fixed by escaping `\` and `&` in the date string before substituting, confirmed correct for a date string containing both. Also fixed: `tests/test-repro.sh`'s second assertion accepted any non-zero exit from `verify-deploy.sh` as "correctly detected staleness," which would also pass on a crash or missing tool - tightened to require the specific `STALE (content mismatch)` line, not just a non-zero exit; `verify-deploy.sh` silently exited 0 against an empty build directory or a missing live directory (no files to check, so the loop never set `status=1`) - both now checked explicitly; added a `require_no_overlap` guard (`scripts/lib.sh`) so a swapped or nested src/dest argument errors loudly instead of a script copying or comparing its own output back into the tree it's traversing. **Self-caught while verifying the overlap-guard fix, not by either review round**: the guard's two error messages were swapped relative to which match condition actually fired - functionally correct exit code, backwards human-readable message. Worth naming directly: a check "passing" by exit code while its own message was wrong is exactly this repo's thesis, one level up, in its own code. Fixed and re-verified in both directions. |
